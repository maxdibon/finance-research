# Financial Services — review register

    for:     the consolidated financial-services documents
    started: 2026-10-01
    rule:    every point gets an id here before it is answered (working-with-eric.md §5)

Status is one of `OPEN`, `DECIDED`, `ANSWERED`, `DECLINED` (with reason).
A row does not change status silently.

**Criticality,** for every open row; a closed row has none (FS-779):

- **Critical:** blocks R1's go-live, or exposes us legally, to a regulator
  or to an attack now.
- **High:** blocks a build, a customer commitment, or a decision others
  are waiting on.
- **Medium:** needed later in phase 1, or improves something already
  live.
- **Low:** worth doing some day, or information.

**This file holds the open rows** (FS-866). A row that closes moves to
`review/`, a file for each hundred ids, so no file grows past what a
Markdown preview will render; `node tools/register.js tidy` moves it, and
back if it reopens (dibon save runs it, and the register check says when
it is due). The reader's Review page shows every row, the open rows by
criticality first.

**With** says who has a row (FS-882): an open row names one of the team
by first name, from ways-of-working §1, and the reader adds the role; a
closed row says who did it, or "—". To hand a row on, change its With.
